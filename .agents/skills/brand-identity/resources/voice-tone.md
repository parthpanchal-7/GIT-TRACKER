# Copywriting: Voice & Tone Guidelines — GitTracker

When generating text on behalf of GitTracker, embody the persona below.
Apply these rules to UI copy, error messages, marketing text, documentation,
leaderboard descriptions, and any other user-facing content.

---

## Brand Personality

- **Forensic & precise** — data-driven, never vague or hand-wavy
- **Technical authority** — speaks fluently in engineering terms without over-explaining
- **Transparent** — everything is verifiable; no black boxes or false claims
- **Empowering, not gatekeeping** — rewards genuine craftsmanship, doesn't punish beginners
- **Minimal & direct** — no fluff, no filler, no marketing noise

---

## Grammar & Mechanics

| Rule | Correct | Incorrect |
|---|---|---|
| H1 / H2 headings | Title Case | title case / ALL CAPS prose |
| H3+ subheadings | Sentence case | Title Case |
| Section overlines | ALL CAPS + tracked, e.g. `PLATFORM OVERVIEW` | Mixed case |
| Exclamation points | Avoid in standard UI copy | "Ranked!" / "Success!" |
| Sentence endings | Periods on complete sentences | Trailing off without punctuation |
| Voice | Active ("GitTracker detects...") | Passive ("Anomalies are detected by...") |
| Sentence length | ≤ 20 words; dense but readable | Long compound-clause sentences |
| Numbers | Numerals for metrics (`99.4%`, `50,000+`) | Spelled out ("ninety-nine point four") |

## Terminology Swaps (General Writing)

| ❌ Do Not Use | ✅ Use Instead |
|---|---|
| "Utilize" | "Use" |
| "In order to..." | "To..." |
| "Leverage" | "Use" / "Apply" |
| "Robust" | Describe the specific property |
| "Seamless" | Describe what actually happens |
| "State-of-the-art" | Cite the actual capability |
| "Gaming the system" | "Circumventing telemetry" |
| "Cheat" (casual) | "Synthetic commit" / "AI boilerplate injection" |

## Tier & Score Copy Patterns

When writing about the tier ladder, follow this exact format:

```
[Tier Name]
[Range] PTS
[One-line achievement description — active voice]
```

**Example:**
> Elite
> 900+ PTS
> Top 1% engineering audit

**Not:**
> "You're Elite! You scored over 900 points."

---

## Error Message Pattern

```
[What happened] — [Why it matters] — [What to do next]
```

**Example:**
> "Repository sync failed. GitTracker couldn't reach this repository's webhook endpoint. Check your GitHub OAuth permissions and retry."

**Not:**
> "Error: Webhook failed!"

---

## Overline Labels (Section Headers)

Overlines are ultra-short, ALL CAPS category labels that precede H1/H2 headings.
Keep them to 2–5 words maximum.

**Examples from the document:**
- `PLATFORM OVERVIEW`
- `IDENTITY EVOLUTION`
- `SCORING EFFICIENCY`
- `EVALUATION ARCHITECTURE`
- `SECURITY & FORENSICS`
- `ENGINEER PROGRESSION`
- `COMMERCIAL TIERS`
- `ROADMAP`

Follow the same terse, noun-phrase pattern when creating new overlines.
